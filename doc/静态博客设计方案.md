## 2. 视觉概念：「玻璃面板」

### 2.1 问题

毛玻璃是最容易被做成模板的风格：深色底 + 紫蓝渐变光球 + 一排同款圆角磨砂卡片 + Inter 字体。这套东西放在任何站点上都成立，因此它不表达任何东西。

要让它成为这个博客的选择，必须回答一个问题：**这块玻璃盖在什么上面？**

### 2.2 概念

工程随笔的世界里有大量真实的玻璃与亚克力：服务器机柜的透明前门、示波器的磨砂面板、CAD 的玻璃视口、标定过的仪器窗口。这些物体有一个共同点——**玻璃的存在是为了让你看见后面那层东西**。

所以本站的玻璃不是装饰，而是一层真正的覆盖物：

- **底层（Substrate）**：一张自定义背景图，全站固定、不随滚动移出视野。
- **面板层（Panel）**：所有 UI 都是"玻璃件"，浮在背景图之上。
- **可验证的玻璃**：背景图里的高频细节（颗粒、光斑边缘）在面板内被抹平成一片匀色，在面板外依然清晰。玻璃的存在不需要任何装饰来暗示——它由模糊本身自证。

这一条是全站唯一"花力气"的地方，其余部分保持安静。

> **一次修正**：这一层最初是 CSS 画出来的工程网格。网格的问题是它太便宜了——1px 的线被 8px 模糊一糊就没有了，玻璃几乎看不出存在。换成有真实细节的背景图之后，同一套参数下模糊的作用变得明确可见。网格方案已整体删除（代码、token、配置一起），只保留"背后必须有东西"这条原则。

### 2.3 厚度即层级

玻璃的物理属性是厚度。本站把厚度定义为**不透明度等级**，并用它表达 UI 层级，而不是用圆角大小或阴影深浅：

| 等级 | tint 不透明度 | 用途 |
| --- | --- | --- |
| `thin` | 0.35 | 代码块、引文、目录、次级信息条 |
| `regular` | 0.62 | 正文容器、卡片、首页模块 |
| `thick` | 0.82 | 顶栏（滚动后）、弹层、模态 |

规则：**层级越高的元素越厚**，因为它在物理上更靠近观察者。

模糊半径是另一条独立的轴，由"背后是什么"决定，见 3.3。

反过来的做法——让代码块比周围更透明——会被刻意用于一处：**正文里的代码块是唯一低于周围厚度的元素**，视觉上像是"透过面板直接看到底层的代码"，呼应"代码是这层玻璃下的东西"。

### 2.4 背光只属于交互

亚克力 + 背光 LED 是真实材质组合，但滥用会变成游戏机箱的氛围灯。约束：

- 背光**不用于装饰**，只出现在两个位置：键盘焦点环、当前导航项指示条。
- 其余所有 hover 反馈用**厚度变化**（tint 上升 0.04）实现，不用上浮、不用阴影加深。

## 3. 设计 Token 系统

全部 token 以 CSS 自定义属性落在 `src/theme/tokens.css`，主题文件只覆盖变量，不写选择器。这是"高自定义"的实现基础。

### 3.1 色彩

**背景亮度预算（核心机制）**

毛玻璃的可读性风险来自"背景不可控"。为此设定一条硬规则：

> Substrate 上的任何像素，其相对亮度必须落在一个受控区间内，使得面板合成后的正文对比度 ≥ 4.5:1，大字号 ≥ 3:1。

有两种方式满足它。**没有背景图时**，底色本身就是一条平坦的低对比灰面，天然落在区间内。**有背景图时**，图片亮度不可控，改由遮罩（scrim）把亮度夹回区间——这条在 10.3 展开，那里有反解出来的遮罩下限。

两种方式都不依赖"图片恰好不太亮"这种运气。

**浅色主题（默认）**

| 角色 | 值 | 说明 |
| --- | --- | --- |
| `--substrate` | `#E9EDF0` | 冷灰雾面，像磨砂铝背板。不用纯白，否则玻璃失去透光感。也是背景图的兜底色 |
| `--panel-tint` | `rgb(255 255 255 / .62)` | 玻璃本体 |
| `--text` | `#141C22` | 正文，实测最差 14.6:1 |
| `--text-dim` | `#5A6873` | 次级文字，实测最差 4.9:1 |
| `--signal` | `#0A736B` | 强调色，实测最差 4.9:1 |
| `--alert` | `#B8382A` | 仅用于错误态与废弃标记，全站极少量 |

> 上表的"最差"指在四种背景（底色、thin / regular / thick 面板）中最不利的一种。强调色与错误态最初取更亮的 `#0B7A72` / `#C8402F`，直接落在底色上时只有 4.4:1，因此压暗了一档。这组数值由构建脚本自动校验，见第 6 节。

**深色主题**

| 角色 | 值 | 说明 |
| --- | --- | --- |
| `--substrate` | `#0E1317` | 冷灰近黑，不用 `#000` |
| `--panel-tint` | `rgb(255 255 255 / .07)` | 深色下靠 tint 极低 + 描边成形 |
| `--text` | `#E4EAEE` | 实测最差 10.3:1（thick 面板） |
| `--text-dim` | `#9AA7B0` | 实测最差 5.1:1 |
| `--signal` | `#2ED3C2` | 深色下用亮版青，实测最差 6.7:1 |
| `--alert` | `#F58570` | 同上，少量 |

> 深色的最差情形出现在 **thick 面板**：白色 tint 叠得越多，底色越亮，浅色文字的对比度反而越低。错误态最初取 `#F2705C`，在 thick 面板上只有 4.3:1，因此提亮了一档。

**为什么是青色**：`#0A736B / #2ED3C2` 取自示波器迹线与 PCB 丝印的仪表青，属于工程领域的真实色彩语汇；它同时避开了当前生成式设计的两大高频配色（暖赤陶 `#D97757` 系与酸性黄绿系），在冷灰底上有明确的存在感，且不会把页面推向"电竞风"。

**主题切换机制**：`<html data-theme="light|dark">`，token 覆盖写在 `:root[data-theme="dark"]` 下。`<head>` 内联一段极短脚本在首次绘制前读取 `localStorage`/`prefers-color-scheme` 写入属性，消除闪白。除 `--signal` 与 `--alert` 外，两套主题共用同一组结构 token。

### 3.2 字体

不使用 Inter / Geist / Roboto 等默认选择。

| 角色 | 字体 | 理由 |
| --- | --- | --- |
| 拉丁正文 / UI | IBM Plex Sans | 出身于工程与仪器语境的超家族，字形带轻微机械感，非默认选择 |
| 代码 / 日期 / 章节编号 | IBM Plex Mono | 与正文同源，用于**结构性数据**（时间、目录编号、行号、版本），而非"小标签装饰" |
| 中文正文 / UI | 系统中文黑体栈 | 优先 PingFang SC，其次微软雅黑、Noto Sans SC。中文系统字体在各自平台上渲染质量最好，且零下载成本 |
| 引文 / 旁注 | 楷体（系统） | `Kaiti SC / STKaiti / KaiTi`，全站只用于 `blockquote` 与旁注块，形成"引用别人的话用楷体"的一致规则；LXGW WenKai 排在字体栈首位，自托管后自动生效 |

> **字体托管**：IBM Plex Sans / Mono 通过 `@fontsource` 自托管，只引入 latin 子集（6 个文件）。中文走系统字体栈（PingFang SC / 微软雅黑 / Noto Sans SC），零下载。楷体同理走系统字体，**不引入任何第三方 CDN 请求**——LXGW WenKai 只作为字体栈里的首选名保留，需要时把 woff2 放进 `public/` 并加一条 `@font-face` 即可启用。整站因此没有任何外部网络依赖。

标题**不用衬线体**。理由：亚克力面板是模切出来的，标题应当像是"刻在面板上"的，因此标题使用 IBM Plex Sans SemiBold + 收紧字距（`-0.02em`），靠字重和间距塑造，不靠换字族。

**字阶**（1.25 倍模块化音阶，正文 17px）

```
--fs-xs    12px   行号、脚注
--fs-sm    14px   元信息、标签
--fs-base  17px   正文    行高 1.75
--fs-md    21px   小标题  h3
--fs-lg    28px   节标题  h2
--fs-xl    40px   页标题  h1
--fs-2xl   56px   首页主张
```

不额外设置"展示字号"，因为 1.25 音阶 + 2xl 上限已经足够；再往上加会变成没有信息量的视觉噪音。

**排版规则**：正文行宽上限 `68ch`（`--measure`）；中英混排时中文字号不变、拉丁字号不变，靠 `font-feature-settings` 与 `text-spacing-trim` 处理中西文间隙，不手动插空格。

### 3.3 玻璃材质参数

```css
:root {
  /* 模糊半径取决于背后是什么，与厚度无关 */
  --glass-blur-flat: 8px;   /* 背后只有平坦底色 */
  --glass-blur-deep: 28px;  /* 背后有正文经过：顶栏、弹层 */
  --glass-saturate:  140%;

  /* 亚克力切边：顶部内高光 + 全周 1px 内描边 */
  --glass-edge-light:
    inset 0 1px 0 rgb(255 255 255 / .75),
    inset 0 0 0 1px rgb(255 255 255 / .35);
  --glass-edge-dark:
    inset 0 1px 0 rgb(255 255 255 / .12),
    inset 0 0 0 1px rgb(255 255 255 / .08);

  /* 背光：只用于焦点与当前项 */
  --backlight: 0 0 0 4px color-mix(in oklab, var(--signal) 22%, transparent);
}
```

玻璃原语：

```css
.panel {
  --panel-tint: var(--tint-regular);
  --panel-blur: var(--glass-blur-flat);

  background-color: var(--panel-tint);
  backdrop-filter: blur(var(--panel-blur)) saturate(var(--glass-saturate));
  border-radius: var(--radius-panel);
  box-shadow: var(--glass-edge);
  transition: background-color var(--dur-base) var(--ease-out);
}
```

`thickness` 只映射不透明度，`backdrop` 只映射模糊半径，两者是独立的轴：

```
<Panel thickness="thin|regular|thick" backdrop="flat|deep">
```

> **实现中的一处修正**：方案最初把模糊半径也绑在厚度上（thin 14px / regular 18px / thick 28px）。实现时发现这个假设站不住：模糊半径要解决的问题是"背后有多少细节要抹掉"，而它和"这个元素在层级里多高"没有关系。而**代码块数量不定，每个都吃一次大半径模糊会带来真实的合成开销**。真正需要大半径的只有顶栏与弹层，因为正文会从它们背后经过。
>
> 于是拆成两条独立的轴：`thickness` 只改不透明度，`backdrop` 只改模糊半径。当前取值是 8px（背后是平坦底色）/ 20px（背后是背景图，见第 10 节），`deep` 一路是 28px / 34px。
>
> 顺带的好处是顶栏"thin → thick"的状态切换现在只改不透明度、不改模糊半径，正好符合第 6 节"不做滚动中改变 backdrop-filter"的约束。

### 3.4 圆角：同心规则

不使用全局统一圆角——那是"卡片套件"的标志。

```
--radius-panel:     16px   外层容器
--radius-control:    8px   按钮、输入框
--radius-chip:       6px   标签、徽标
```

嵌套时的硬规则：`内层圆角 = 外层圆角 − 内边距`。这条公式可直接写进组件，避免出现"盒子里套盒子但圆角一样大"的视觉噪音。

### 3.5 间距与栅格

```
--space-1  4px     --space-5  24px
--space-2  8px     --space-6  32px
--space-3  12px    --space-7  48px
--space-4  16px    --space-8  72px
```

所有间距取自 4px 基数，且**必须**来自这组 token，不允许出现裸数值。

页面栅格：桌面 12 列，最大宽度 1120px，两侧 32px 内边距；平板降为 8 列；移动端单列 20px 内边距。

### 3.6 动效

**唯一的编排时刻**：首屏加载。

1. 底纹以 0.6s 浮现（实测做法：`opacity 0 → 1` 配合 `scale 1.06 → 1`，只用合成器属性，逐帧重绘整屏不在预算内）；
2. 首页模块依次落位，每块 `translateY 12px → 0`，同时模糊半径从 `--glass-blur-deep` 收敛到 `--glass-blur-flat`（表达"吸附到位"），间隔 80ms；
3. 总时长不超过 700ms，只发生一次，不随滚动重复。

**交互响应**：顶栏滚动后从 `thin` 升到 `thick`（有信息含义：它离你更近了，且只改不透明度，见第 6 节）；面板 hover 提升 tint 约 0.05；焦点出现背光。

**明确不做**：

- 每个 section 的 fade-and-slide-up 入场；
- 每张卡片的 hover 上浮 + 阴影加深；
- 视差、滚动触发的缩放。

`prefers-reduced-motion: reduce` 下关闭 1、2 与顶栏过渡，仅保留即时状态切换（不透明度/颜色），不保留位移与模糊动画。

## 4. 布局与页面

### 4.1 首页

目标是"让最新一篇有分量"，而不是把所有内容切成一排等大卡片。因此采用**非对称**结构：一篇主推 + 两块辅助面板。

```
┌──────────────────────────────────────────────────────────────────────┐
│ ▓ 顶栏（thin → 滚动态 thick）  文章 归档 系列 标签 关于    搜索 RSS 浅色 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   背景图里的细节在面板外清晰，在面板内被抹平 —— 玻璃不需要别的证据      │
│                                                                      │
│   ┌ 站点主张 ────────────┐   ┌ 最近一篇 ──────────────────────────┐  │
│   │ 我写下工程里的取舍， │   │ 2026-09-12                          │  │
│   │ 以及那些当时以为对了 │   │ 把 Redis 当队列用的三个反模式       │  │
│   │ 的错。               │   │                                     │  │
│   │                      │   │ 12 分钟                             │  │
│   │ 这里没有教程。只有做 │   │ Redis  队列  架构                   │  │
│   │ 过的事、量到的数。   │   │                                     │  │
│   └──────────────────────┘   └─────────────────────────────────────┘  │
│                                                                      │
│   ┌ 最近更新 ────────────────────┐  ┌ 现在 ───────────────────────┐   │
│   │ 2026-09-12  把 Redis 当队列… │  │ 在做  把索引服务挪到多副本    │   │
│   │ 2026-08-30  位图模糊匹配…    │  │ 在读  DDIA 第三遍            │   │
│   │ 2026-08-04  为什么我把索引…  │  │ 在学  Rust 异步运行时调度    │   │
│   └──────────────────────────────┘  └──────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────────┘
```

> 线框里的顶栏按实现更新过：RSS 放在搜索与主题切换之间。元信息也不再用中点或斜杠串成一串，而是对齐的字段与标签。

首页由**模块数组**驱动（见 5.3），默认顺序为：主张 → 最新一篇 → 归档 → 现在。改顺序 = 改配置文件数组顺序，不需要动布局代码。

元信息（日期、阅读时长、标签）用 mono 字体排成对齐的小栏位，**不使用中点串联**（`Rust · 缓存 · 队列` 是模板化写法），改为换行对齐的字段。

### 4.2 文章页

单栏阅读为主，正文 `--measure: 68ch`，左对齐（不用两端对齐，中文两端对齐易出现字距崩坏）。

```
┌──────────────────────────────────────────────────────────────┐
│ ▓ 顶栏                                                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   2026-09-12   12 分钟   Rust / 缓存                          │  ← mono 元信息
│                                                              │
│   把 Redis 当队列用的三个反模式                                │  ← 40px SemiBold
│                                                              │
│   ┌ 正文面板 regular ──────────────────┐  ┌ TOC thin ──────┐ │
│   │ 段落文字…                          │  │ 1 背景          │ │
│   │                                    │  │ 2 三个反模式    │ │
│   │ ┌ 代码块 thin（比正文更透明）──────┐│  │ 3 替代方案      │ │
│   │ │ fn enqueue(...)                  ││  │                 │ │
│   │ └──────────────────────────────────┘│  │ （滚动高亮）    │ │
│   │                                    │  └─────────────────┘ │
│   │ ┌ 旁注 thin + 楷体 ────────────────┐│                      │
│   │ │ 这里踩过的坑值得单独说一句。      ││                      │
│   │ └──────────────────────────────────┘│                      │
│   └────────────────────────────────────┘                      │
│                                                              │
│   ┌ 上一篇 / 下一篇 ──────────────────────────────────────┐   │
│   └───────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

要点：

- 正文区**永远**使用最高可读性配置（`regular` 厚度 + `--text` 全黑度），不允许视觉实验侵蚀阅读区；
- 代码块用 `thin`，是唯一"比周围更透明"的元素；
- 旁注块用 `thin` + LXGW WenKai，与引文共用同一套样式，形成固定语义；
- TOC 为 `thin` 面板，滚动高亮用 `--signal` 左侧竖条指示，不用加粗（加粗会引起正文宽度跳动）；
- TOC 在 DOM 中**前置**于正文，宽屏时才用 `order` 放到正文右侧。视觉顺序与 DOM 顺序不一致会让键盘焦点在页面上跳来跳去，窄屏下两者保持一致。

### 4.3 归档 / 标签 / 系列

- 归档：按年月分组的紧凑列表，mono 日期列与标题列左右对齐，行悬停提升 tint；不改为卡片网格（列表本就是归档的正确形态）。
- 标签：芯片式，但**标签本身无编号、无图标**，只是文字 + `chip` 圆角。
- 系列：同一系列的文章按顺序编号——这里**是**真正的序列，因此使用编号标记（章节序号用 mono 字体），符合"结构装置编码信息"的原则。

### 4.4 对齐

全站左对齐。唯一居中的是 404 页面与空状态文案，因为那里没有需要对齐的相邻内容。

## 5. Astro 架构与自定义机制

"自定义程度高"要落到具体机制上，否则只是口号。

### 5.1 目录结构

```
src/
  site.config.ts            站点配置（唯一需要改的文件）
  theme/
    tokens.css              全部设计 token
    themes/
      light.css             仅覆盖变量
      dark.css
    base.css                重置、排版基线
    glass.css               玻璃原语与厚度映射
  components/
    glass/
      Panel.astro           唯一的玻璃原语
      PanelStack.astro      同心圆角容器
    ui/                     按钮、标签、TOC、顶栏…
    home/                   首页模块（每个模块一个组件）
    post/                   文章页区块
  layouts/
    BaseLayout.astro        substrate + 玻璃层 + head 注入
    PostLayout.astro
  content/
    posts/*.md
  content.config.ts         Zod schema
  pages/
    index.astro
    posts/[...slug].astro
    archive.astro  tags/[...tag].astro  series/[...name].astro
    about.astro  rss.xml.ts  404.astro
```

### 5.2 组件分层规则

业务组件**不允许**直接写 `backdrop-filter`、`background`（面板类）、`box-shadow`（边缘类）。所有玻璃效果必须经由 `Panel.astro`：

```
<Panel thickness="regular" radius="panel" as="article">
  ...
</Panel>
```

这条约束让"换皮"只需改动一个文件，也让新页面天然获得一致的材质表现。

### 5.3 配置驱动

`site.config.ts` 是站点唯一入口：

```ts
export default {
  site: { title, description, url, author, lang },
  nav: [ { label: '文章', href: '/posts' }, ... ],
  social: [ ... ],
  home: [
    { type: 'statement', props: { ... } },
    { type: 'latest',    props: { ... } },
    { type: 'archive',   props: { limit: 5 } },
    { type: 'now',       props: { ... } },
  ],
  features: { search: true, toc: true, katex: false, comments: false },
  theme: { default: 'light', accent: 'signal-teal', fonts: 'plex' },
} satisfies SiteConfig;
```

首页模块数组的顺序**就是**渲染顺序，每个 `type` 对应一个组件，并用 `satisfies` 保证类型安全——配置写错在 `astro check` 阶段报错，而不是运行时白屏。

`features` 开关决定构建时是否引入对应岛屿，关闭即零产物体积。

### 5.4 内容管线

使用 Astro Content Collections，`content.config.ts` 中定义 Zod schema 做构建期校验：

```
title / date / updated? / summary / tags[] / series? / order? / draft / lang?
```

效果：frontmatter 少字段、日期格式错误、标签类型不对，在构建时直接失败并给出可读报错。这比"页面上悄悄渲染出空日期"要好得多。

### 5.5 交互岛屿

| 交互 | 实现 | 说明 |
| --- | --- | --- |
| 主题切换 | 普通打包脚本 | 需即时响应，体积极小；标签状态由 CSS 依据 `html[data-theme-mode]` 决定，首屏即正确 |
| 搜索 | `is:inline` 脚本 | Pagefind 静态索引，无后端；Pagefind 的 UI 资源在首次打开时动态注入，开发环境不会 404，索引缺失时给出可执行的提示 |
| 代码复制 | 普通打包脚本 | 逐个代码块注入按钮，共用一个脚本 |
| TOC 滚动高亮 | 普通打包脚本 | 用 `scroll` + `requestAnimationFrame` 计算当前章节，比 IntersectionObserver 更能覆盖"停在页首"和"滚到页尾"两种情况 |
| 数学公式 | 构建期 | KaTeX 在构建时渲染为静态 HTML，不引入运行时 |

**与方案的一处偏差**：方案原本写"用 `client:visible` 按需加载岛屿"。`client:*` 指令只对框架组件生效，本站没有引入任何框架运行时，因此这些脚本是 Astro 的普通组件脚本，只在**用到该组件的页面**上打包引入。它们各只有几百字节，按视口延迟加载没有收益，因此不为此引入框架。

除以上外**零 JS**。首屏 JS 只有顶栏滚动状态与主题切换两段。

### 5.6 代码高亮

Shiki 双主题（`vitesse-light` / `vitesse-dark`，冷灰底 + 青绿强调，与整体配色同源）。

关键一项配置是 `defaultColor: false`：默认情况下 Shiki 会把浅色主题的颜色**内联**写进 HTML，只把深色放进变量，两套主题因此走两条不同的 CSS 路径。关掉默认着色后，Shiki 只输出 `--shiki-light` / `--shiki-dark` 变量，浅色与深色变成同一条规则、只换变量，切换主题时无需重新高亮。

代码块的背景由本站的 `thin` 面板接管（覆盖 Shiki 的内联背景），因此代码块成为全站唯一"比周围更透明"的元素。支持：指定行高亮、行号、右上角复制按钮。

### 5.7 图片

`astro:assets` 构建期优化（AVIF/WebP + 多尺寸 `srcset`），占位使用显式宽高避免布局抖动。封面图在列表中使用 `thin` 玻璃相框——图上是玻璃，不是图上叠阴影。

## 6. 可访问性、性能与降级

这几项是"美观"之外的品质底线，不做声明式承诺，做可校验的约束。

**对比度**

- 遵守 3.1 的背景亮度预算：没有背景图时靠平坦底色天然满足；有背景图时靠遮罩把亮度夹回区间。
- 文字可能落在四种背景上（底色、thin / regular / thick 面板），因此**逐一校验、取最差情形**：正文、次级文字、强调色、错误态都要达到 4.5:1。
- 这条规则不靠人工判断：`scripts/verify-contrast.mjs` 直接读主题 CSS 里的 token，做 sRGB 合成后计算 WCAG 对比度，不达标就让构建失败。当前实测（最差情形）：

  | | light | dark |
  | --- | --- | --- |
  | 正文 | 14.63:1 | 10.35:1 |
  | 次级文字 | 4.87:1 | 5.10:1 |
  | 强调 / 链接 | 4.85:1 | 6.70:1 |
  | 错误态 | 4.90:1 | 5.07:1 |

**backdrop-filter 的性能约束**

- 模糊半径按"背后是什么"分级（8px / 20px / 28px / 34px），不按层级。背后只有平坦底色时用 8px —— 代码块在长文里可能有十几个，每个都吃一次大半径模糊是真实的合成开销。
- 不做滚动中改变 `backdrop-filter` 动画，只改变不透明度。顶栏的 thin → thick 切换因此只改背景色。
- 移动端再降一档：无背景图是 6px / 18px，有背景图是 14px / 22px。有背景图时必须单独写一条移动端规则 —— `backdrop.css` 里那条选择器优先级更高，会把 tokens.css 的降级整个架空，这点在实现时踩过一次。首页在窄屏下是单列堆叠，同屏面板数自然减少。
- 首页桌面端同屏 5 块面板（顶栏 + 4 个模块），是全站数量最多的一屏。再加首页模块就是在加合成层，不要让它继续涨。

**降级**

```css
@supports not (backdrop-filter: blur(1px)) {
  .panel { background: color-mix(in oklab, var(--panel-tint) 96%, var(--substrate)); }
}
```

不支持模糊时面板转为近乎不透明——布局与层级完全不变，只是失去透明感。

**其他**

- 键盘焦点：`2px solid var(--signal)` + `2px offset`，任何情况下可见，不允许 `outline: none`。
- 语义 HTML：`article` / `nav` / `aside` / `time` / `figure`，标题层级不跳级。
- 打印样式：底纹与玻璃全部关闭，转为白底黑字——玻璃在纸上没有意义。
- 动效：尊重 `prefers-reduced-motion`（见 3.6）。

## 10. 背景媒体模式

第 2 节说「玻璃之所以是玻璃，因为它盖着东西」。这一节就是决定盖什么，以及**默认盖的是哪一张**。

默认背景是随仓库发布的一张 SVG（`public/images/backdrop-default.svg`，约 1KB）。它刻意不是照片：必须自包含、无外部请求，又要让模糊效果有东西可糊。结构上只有三样东西——冷调底色、几片柔光、一层细颗粒。**细颗粒是关键**，它是唯一的高频细节，玻璃面板的模糊正是靠"把颗粒抹平"自证的。

### 10.1 换成你自己的图

```
1. 把图放进 public/images/
2. 改 src/site.config.ts 的 background.image
3. npm run verify:contrast   # 确认遮罩强度够用
   npm run build
```

全部旋钮：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `image` | 内置 SVG | 图片路径，放 `public/` 下。设为 `null` 会退化成纯色底 |
| `video` | `null` | 视频路径；建议同时保留 `image` 作为海报与兜底 |
| `scrim` | `0.4` | 遮罩强度。**有下限**，见 10.3 |
| `tone` | `'auto'` | `auto` 跟随明暗主题；`dark` / `light` 固定一种，见 10.4 |
| `blur` | `0` | 背景自身虚化，等价于给整个画面加一层景深 |
| `position` | `'50% 50%'` | 媒体的 `object-position`，竖图或移动端常需调 |
| `scope` | `'all'` | `all` 全站 / `home` 只在首页 |

### 10.2 底纹从一层变三层

```
.substrate（fixed, inset 0）
  ├─ background-color: var(--substrate)   ① 底色兜底，媒体未加载时不闪白
  ├─ .substrate__media   <img> / <video>  ② 媒体，object-fit: cover
  └─ .substrate__scrim   <div>            ③ 遮罩，给面板一个亮度下限
```

> 曾经还有第四层：CSS 画出来的工程网格。它被整体删掉了——原因见第 2 节的修正说明，网格的 1px 细节被模糊一糊就没了，玻璃反而看不出存在。

媒体用负 inset 把盒子放大 `2 × blur`，让虚化的边缘溢出落在视口之外 —— 所以 `blur` 调大也不会在四周露出糊边。视频在 `prefers-reduced-motion: reduce` 下直接隐藏、退回静态图，这一点参考站点漏了。

> 实现时踩到一个坑：基线的 `img { max-width: 100% }` 会把这个放大补偿截断，宽度被压回 100%，负 inset 白给了，`blur` 一大四周就露糊边。`.substrate__media` 里那句 `max-width: none` 就是为它写的。实测（视口 822×540、blur 24px）：媒体盒应为 918×636，修之前宽度只有 822px。

配置值不写进 CSS，而是由 `BaseLayout` 作为 CSS 变量内联到 `<html>` 上，`site.config.ts` 始终是唯一数据源。

### 10.3 遮罩不是装饰旋钮，是可读性的保证

这是本节最要紧的一点。第 3.1 节那条「底纹亮度预算」的前提是**底纹亮度由我们控制**。换上用户自己的图之后这个前提没了。

但遮罩能把亮度重新夹进一个区间。面板的合成结果可以精确解出来：

```
panel = α_tint + α_scrim − α_tint · α_scrim
```

把最极端的一档代进去（`dark` 配纯白图、`light` 配纯黑图），实测结果是：

| 调性 | 面板 | 实测（遮罩 0.40） | 最紧的约束 | 遮罩下限 |
| --- | --- | --- | --- | --- |
| dark | thin | 4.89:1 | 次级文字 `--text-dim` | **0.35** |
| dark | regular | 6.91:1 | 次级文字 | 0 |
| dark | thick | 9.01:1 | 次级文字 | 0 |
| light | thin | 4.84:1 | 错误态 `--alert` | **0.33** |
| light | regular | 6.20:1 | 错误态 | 0 |
| light | thick | 7.56:1 | 错误态 | 0 |

两条结论：

1. **只有 thin 面板是紧的。** regular 与 thick 已经足够厚，遮罩为 0 也能达标，所以下限完全由最薄的那一档决定。这正是 10.5 说的「动态范围收窄」—— 玻璃越薄，能透过来的背景差异越大，文字越没有余量。
2. **两种调性的瓶颈不是同一个 token。** dark 卡在次级文字（浅字压暗玻璃，余量小），light 卡在错误态（红字压白玻璃）。这也是校验脚本要对四个文字 token 逐一取最坏值、而不是只看正文的原因 —— 最初手算时只盯着次级文字，差点漏掉 light 调性的错误态。

所以**遮罩有下限**，而且这个下限不是拍出来的。`scripts/verify-contrast.mjs` 会：按 `tone` 取对应的最坏图片（`dark` 取纯白、`light` 取纯黑），从 `site.config.ts` 读配置的遮罩强度，二分反解出所需的最小值，不够就让构建失败并直接告诉你该改成多少。默认 0.40 相对 0.35 / 0.33 留了一点余量。

### 10.4 调性默认跟随明暗主题

`tone` 的默认值是 `auto`：深色主题配暗玻璃浅字，浅色主题配白玻璃深字。切换主题时调性一起走，**顶栏的主题按钮保持有效**。

一开始我把 `tone` 设计成与主题解耦的独立配置，默认锁死 `dark`，理由是"背景图需要一套稳定的遮罩，对比度才可预测"。这个理由后来站不住：两种调性都已经按最坏图片（`dark` 对纯白、`light` 对纯黑）单独校验过对比度，都达标。既然都安全，就没有理由牺牲主题切换——锁死 `dark` 会让主题按钮变成一个什么都不做的控件。

`dark` / `light` 仍然保留为显式取值，用于"这张照片只适合一种用法"的情况（比如一张高对比夜景，配浅色遮罩会糊成一片灰）。代价是此时主题切换不再影响配色，顶栏那个按钮会失去作用——属于用配置换效果，自己清楚就行。

实现上有个必须注意的点：调性属性要和主题在**同一处**定下来。`data-theme` 由 `<head>` 里的内联脚本在首绘前写入，如果 `data-backdrop-tone` 晚一步再设，就会先按默认调性画一帧再跳变。

### 10.5 两个代价

**面板变厚了。** 背景模式下三档 tint 是 `0.6 / 0.76 / 0.9`，比常规主题高不少。原因是透明的动态范围收窄：能透过来的背景差异越大，文字越没余量。`--text-dim` 在暗调下取到 `#b8c3ca` 才刚过 4.5:1 —— 这是透明面板的固有代价，不是调参能消掉的。换来的是「代码块比正文更透明」这条设计依然成立（0.6 < 0.76）。

**模糊半径上调了。** 有背景图时 `flat` 从 8px 提到 20px（移动端 14px）：第 3.3 节的规则是「半径取决于背后是什么」，而背后现在是含有真实颗粒的照片，不再是平坦底色。移动端那条必须单独重写一遍，否则会被优先级更高的背景规则架空。

### 10.6 性能提醒

- 顶栏的 `backdrop-filter` 会**逐帧重算**背后的视频，这是背景视频最贵的一处，移动端尤其明显。
- 4MB 级别的循环视频比整站其他静态资源加起来都大。视频建议配 `scope: 'home'`，别让它出现在每一篇文章页。
- 背景图不需要很大：它被虚化、被遮罩压过、又被面板挡住大半，超过 2560px 宽基本是浪费。
