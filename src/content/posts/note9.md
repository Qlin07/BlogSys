# 内存分区概览

一个 C++ 程序运行起来后，进程的地址空间通常会被划分成若干区域。不同平台、不同编译器细节会有差异，但常见模型大致如下：

```
高地址
  ↑ ┌─────────────────────┐
  │ │        栈 Stack     │  ← 局部变量、函数调用信息，向低地址增长
  │ ├─────────────────────┤
  ↑ │                     │
  │ │        堆 Heap      │  ← new/malloc 动态分配，向高地址增长
  │ │                     │
  ↑ ├─────────────────────┤
  │ │  未初始化数据段 BSS  │  ← 未初始化的全局变量、静态变量
  │ ├─────────────────────┤
  ↑ │  已初始化数据段 Data │  ← 已初始化的全局变量、静态变量
  │ ├─────────────────────┤
  │ │  常量区/只读数据段    │  ← 字符串字面量、const 全局量等
  ↑ ├─────────────────────┤
  │ │     代码区 Text      │  ← 程序机器指令
  │ └─────────────────────┘
低地址
```

这只是一个典型示意图，实际布局和地址增长方向依平台而定。

------

## 一、栈区

栈区主要存放：

- 函数的局部变量；
- 函数参数；
- 返回地址；
- 一些寄存器保存信息。

例如：

```C++
void f() {
    int a = 10;      // a 在栈上
    double b = 3.14; // b 在栈上
}
```

特点：

- 由编译器自动分配和释放；
- 生命周期由作用域决定；
- 分配和释放非常快；
- 空间通常较小，递归太深会栈溢出。

------

## 二、堆区

堆区用于**动态内存分配**，比如：

```C++
int* p = new int(10);   // 堆上分配一个 int
delete p;

int* arr = new int[100]; // 堆上分配数组
delete[] arr;
```

或者 C 风格：

```C
int* p = (int*)malloc(sizeof(int));
free(p);
```

特点：

- 由程序员手动申请和释放；
- 生命周期从申请到释放，不由作用域决定；
- 空间通常比栈大；
- 分配释放较慢，容易产生内存泄漏和碎片。

------

## 三、静态/全局区

这个区域存放：

- 全局变量；
- 静态局部变量；
- 静态全局变量；
- 类的静态成员变量。

例如：

```C++
int g = 10;              // 已初始化全局变量，通常在 Data 段
int g2;                  // 未初始化全局变量，通常在 BSS 段

void f() {
    static int s = 20;   // 静态局部变量，也在静态区
}
```

特点：

- 生命周期从程序开始到程序结束；
- 只初始化一次；
- 未初始化的全局/静态变量通常会被自动置零；
- 不属于某个函数调用，函数返回后仍然存在。

------

## 四、常量区 / 只读数据段

常量区通常存放：

- 字符串字面量；
- 一些只读的常量数据。

例如：

```C++
const char* s = "hello";  // "hello" 通常在常量区
```

注意：

- `"hello"` 本身是只读的，修改它是未定义行为；
- `s` 这个指针变量本身可能在栈上，但它指向常量区。

```C++
char* p = "hello";  // C++11 起这种写法不推荐，应写 const char*
p[0] = 'H';         // 未定义行为，可能崩溃
```

另外，`const` 变量不一定都在常量区。例如局部 `const int x = 10;` 通常仍在栈上，只是不可修改。是否放入只读段，取决于实现和上下文。

------

## 五、代码区

代码区存放程序编译后的机器指令，也就是函数体对应的代码。

特点：

- 通常是只读的，防止程序意外修改指令；
- 可以被多个进程共享，例如同一个可执行文件启动多个实例；
- 函数指针指向的就是代码区中的地址。
