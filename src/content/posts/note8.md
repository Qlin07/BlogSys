# 平衡树的概念以及常见平衡树

## 为什么需要平衡树

普通的二叉搜索树（BST）在理想情况下，树高大约是 `log n`，查找、插入、删除都是 **O(log n)。**

但如果插入顺序不好，BST 会退化成链表。

**平衡树**就是为了解决这个问题：通过一些规则和调整操作，让树始终保持比较“矮胖”，从而保证树高为 **O(log n)**，保证**查找插入和删除**的时间复杂度为O(log n)

## 四种旋转

### 一、失衡的四种情况

当插入或删除导致某个节点失衡时，根据新节点插入位置的不同，分为四种情况：

| 情况 | 含义                 | 调整方式       |
| ---- | -------------------- | -------------- |
| LL   | 在左子树的左子树插入 | 右旋           |
| RR   | 在右子树的右子树插入 | 左旋           |
| LR   | 在左子树的右子树插入 | 先左旋，再右旋 |
| RL   | 在右子树的左子树插入 | 先右旋，再左旋 |

### 二、左旋右旋

先单独讲一下左旋和右旋，以左旋为例：

```C++
        x                  y
       / \      变化      / \
      a   y    -----→    x   c
         / \            / \
        b   c          a   b
```

以上是关于x的左旋，a、b、c都是x和y的子树，x上面还有可能的父节点，但整个操作只更改x和y，并没有变更子树的结构，只更改了子树的父节点。

```C++
struct Node {
    int key;
    Node* left;
    Node* right;
    Node* parent; // 一个指向父节点的指针，方便旋转
};

Node* NIL;   // 所有叶子都指向它，哨兵指针
Node* root = NIL; // 初始化根指针
void leftRotate(Node* x) {
    //初始化y:
    Node* y = x->right;

    // y 的左子树变成 x 的右子树:
    x->right = y->left;        
    if (y->left != NIL) { // 子树非空则更改其父节点
        y->left->parent = x; 
    }

    //如果x有父节点，将x.parent指向y，否则y代替x，成为root
    y->parent = x->parent;
    if (x->parent == NIL) {
        root = y;
    }
    else if (x == x->parent->left) {
        x->parent->left = y;
    }
    else {
        x->parent->right = y;
    }

    //x,y互指
    y->left = x;
    x->parent = y;
}
```

右旋则与左旋的操作相反即可

### 三、LL 型：右旋

初始状态：

```
        30
       /
      20
     /
    10
```

新节点 `10` 插入在 `30` 的左子树的左子树，属于 LL 型。
调整方法：对节点 `30` 进行**右旋**。

右旋过程：

1. 让 `20` 成为新的根；
2. `30` 变成 `20` 的右子节点；
3. `20` 原来的右子树（如果有）挂到 `30` 的左子树。

旋转后：

```
        20
       /  \
      10   30
```

恢复平衡。

------

### 四、RR 型：左旋

初始状态：

```
    10
      \
       20
         \
          30
```

新节点 `30` 插入在 `10` 的右子树的右子树，属于 RR 型。
调整方法：对节点 `10` 进行**左旋**。

左旋过程：

1. 让 `20` 成为新的根；
2. `10` 变成 `20` 的左子节点；
3. `20` 原来的左子树挂到 `10` 的右子树。

旋转后：

```
        20
       /  \
      10   30
```

恢复平衡。

------

### 五、LR 型：先左旋，再右旋

初始状态：

```
        30
       /
      10
        \
         20
```

新节点 `20` 插入在 `30` 的左子树的**右子树**，属于 LR 型。
如果直接对 `30` 右旋，会变成：

```
        10
          \
           30
          /
         20
```

仍然不平衡。所以需要两步：

1. 先对 `30` 的左子节点 `10` 进行**左旋**；
2. 再对 `30` 进行**右旋**。

第一步，对 `10` 左旋：

```
        30
       /
      20
     /
    10
```

第二步，对 `30` 右旋：

```
        20
       /  \
      10   30
```

恢复平衡。

------

### 六、RL 型：先右旋，再左旋

初始状态：

```
    10
      \
       30
      /
     20
```

新节点 `20` 插入在 `10` 的右子树的**左子树**，属于 RL 型。

调整步骤：

1. 先对 `30` 进行**右旋**；
2. 再对 `10` 进行**左旋**。

第一步，对 `30` 右旋：

```
    10
      \
       20
         \
          30
```

第二步，对 `10` 左旋：

```
        20
       /  \
      10   30
```

恢复平衡。

# AVL树的插入与删除的调整流程

在了解对树的旋转操作后，就可以来实践一下如何动态调整一个树了
以AVL树为例，AVL 树是最早被提出的自平衡二叉搜索树之一。它给每个节点定义一个**平衡因子（BF）**，计算方法为

```C++
平衡因子 = 左子树高度 - 右子树高度
```

BF 的绝对值不能大于1，否则为非法，即不平衡状态，需要通过旋转来达到平衡，下面来看具体插入流程：

首先来看节点的定义：

```C++
struct Node {
    int key; //节点的值
    
    Node* left;
    Node* right;
    Node* parent;
    
    int height,BF; // AVL 树特色；
};
```

## 插入

先按照普通BST规则进行插入，新节点一定是叶子节点，高度为1，初始BF=0
从父节点开始，向上回溯到根，具体操作为：

1.对每个祖先节点更新它的高度：

```C++
height = max(left->height,right->height) + 1;
```

2.然后计算平衡因子：

```C++
BF = left->height - right->height
```

3.检查这个节点的平衡因子：

- 如果BF合法，继续向上
- 如果BF非法（一般等于`±2`），说明此节点子树失衡，需要旋转。

4.判断旋转类型

- `BF == 2`，看左孩子：
  - 左孩子 `BF >= 0`：LL 型，右旋一次；
  - 左孩子 `BF < 0`：LR 型，先左旋左孩子，再右旋当前节点。
- `BF == -2`，看右孩子：
  - 右孩子 `BF <= 0`：RR 型，左旋一次；
  - 右孩子 `BF > 0`：RL 型，先右旋右孩子，再左旋当前节点。

> BF=0的情况比较灵活，可以是LL或者LR，但为了算法简单，避免两次旋转操作，一般都视作单边，如LL或者RR的情况

5.旋转后，子树高度恢复

AVL树插入导致的失衡，一次旋转（指四种类型的旋转之一，而非左旋右旋）就能恢复整棵树的平衡

## 删除

删除比插入复杂，因为删除可能降低子树高度，导致**多个祖先节点依次失衡**，所以需要一直向上调整到根。

1.按BST规则删除节点

- 如果删除的是叶子，则直接删除
- 如果删除的节点只有一个孩子，用孩子替代
- 如果有两个孩子，通常用**中序后继或中序前驱**替代，然后删除那个后续或前驱节点。

2.从被删除节点的父节点开始，向上回溯到根，对每个祖先节点更新高度，计算BF

3.检查BF，如果BF合法，继续向上，否则执行旋转

4.旋转后继续向上检查
	删除与插入不同，一次旋转后子树高度仍可能比原来低，上层可能也已经失衡，所以要一直向上检查到根节点。

### 删除举例

由于删除较为复杂，举一个例子

```C++
        50
       /  \
      30   70
     /  \    \
    20  40   80
       /
      35
```

对于这个树，我们尝试删除80，80没有子节点，不用找替代

```C++
        50
       /  \
      30   70
     /  \    
    20  40   
       /
      35
```

现在开始更新，公式如下：

```C++
height = max(left.height , right.height) + 1;
BF = left.height - right.height;
```

更新70：

- 70没有子节点，作为叶子节点，height=1，BF=0

合法，不用旋转

更新50：

- 50节点，根据公式，height=4，BF=2

非法，需要旋转：

​由于50的BF>0，所以要找左节点
左节点30的BF=-1<0，所以是LR形式。

先对30左旋，得到

```C++
        50
       /  \
      40   70
     /
    30
   /  \
  20  35
```

然后对50右旋

```C++
        40
       /  \
      30   50
     /  \     \
    20  35    70
```

最终达到平衡

# 红黑树的插入与删除的调整流程

红黑树也是一种自平衡二叉搜索树。与AVL引入平衡因子不同，它在每个节点上增加一个颜色位：红色或黑色，通过颜色规则来维持近似平衡

还是先看节点定义：

```C++
enum Color { RED, BLACK }; //enum是C++中的枚举类型定义，也可以用bool替代

struct Node {
    int key; //节点值
    
    Node* left;
    Node* right;
    Node* parent;   
    
    Color color; //红黑树特色
};

Node* NIL;   // 所有叶子都指向它，颜色为黑，哨兵节点，方便统一操作
Node* root = NIL; //初始化根节点，一开始为空
```

为了维持红黑树的平衡，需要满足五条性质：

1. **每个节点是红色或黑色。**

2. **根节点是黑色。**

3. **每个叶子节点（NIL 空节点）是黑色。**

4. **红色节点的两个子节点必须是黑色。**
   也就是说，**不能出现连续两个红色节点**。

5. **从任一节点出发，到其所有后代叶子节点的路径上，黑色节点数量相同。**
   这个数量称为该节点的**黑高**。

其中关键性质是4和5

这五条性质共同保证了：**从根到最远叶子的路径长度，不会超过到最近叶子路径长度的两倍。**
因此树高始终是 O(log n)，查找、插入、删除都能保持在 O(log n)。

## 插入

红黑树插入新节点时，**新节点默认为红色**，因为插入红色节点不会改变任何路径上的黑高，只会可能违反性质 4：**红色节点的子节点必须是黑色**。所以插入后的调整，核心就是：**如果出现红红相连，就通过变色和旋转来修复。**

先声明几个符号，假设新插入节点为`z`，它的父节点为`p`，祖父节点为`g`，叔叔节点为`u`，那么就有以下四种类型（由于哨兵节点的存在，插入新节点时一定会有以下四种结构）。

```C++
        g               g                   g                 g
       / \             / \                 / \               / \
      p   u           p   u               u   p             u   p
     /                 \                     /                   \
    z                   z                   z                     z
```

- 情况1：`p`是黑色，没有红红相连，无事发生。插入直接结束，无需调整

- 情况2：`p`是红色，此时`g`一定是黑色，这时要看`u`的颜色

  - 2.1：`u`是红色：变色

    - 把`p`和`u`变黑
    - 把`g`变红；
    - 把`g`当作新的`z`，继续向上检查。如果`g`是根节点则强制变黑。

    为什么可行？

    通过把`p`和`u`变黑的同时把`g`变红，就能保证`g`这个子树的黑高不变；

    为什么向上？

    因为`g`变成红色后可能会和`g`的父节点变成红红，所以还要向上。

  - 2.2:`u`是黑色：旋转+变色

    - 根据`z`,`p`,`g`的相对位置，决定四种类型的旋转，这点和AVL一样

    - 旋转完成后变色：根据旋转后的父子关系从上到下变为黑->红->黑

      ​	（即对调最后一步状态下的祖父节点和父节点的颜色）

    - 完成后结束，不用继续向上

    为什么不用继续向上？

    因为原本祖父位置的黑高没有改变，旋转后子树新根涂黑、其两子涂红。

## 删除

删除比插入复杂得多，因为如果删除一个黑色节点会破坏性质5：**从任一节点到其所有后代叶子节点的路径上，黑色节点数量相同**。为了修复这种不平衡，需要引入“双重黑色”的概念。

---

红黑树删除和普通 BST 一样，分三种情况：

1. **删除节点是叶子**：直接删除。
2. **删除节点只有一个孩子**：用孩子替代它。
3. **删除节点有两个孩子**：用中序后继（或中序前驱）的**值**替代它（注意是值），然后删除那个后继节点。

步骤3在实现过程中会回归到步骤1、2中，所以这里只讨论1、2两种情况。在删除节点后的工作主要是修复红黑树性质的过程，所以这里按情况讨论

### 一、只有左/右子树：直接替代，然后变黑

如果被删除的节点只有一个子树，那么**被删除的节点一定是黑色节点**，**子节点一定是红色**，**并且该红色子节点没有任何其他子节点**。下面一一解释

- **被删除的节点一定是黑色节点**：因为不能是红色节点。红色节点只能是叶子节点或者两个黑色子节点，否则原红黑树不成立。
- **子节点一定是红色**：如果只有一边子节点还是黑色，会违反性质5。
- **该红色子节点没有任何其他子节点**：这里的子节点不包括NIL黑色哨兵节点。首先这个子节点不能是红色，否则违反性质4，如果是黑色违反性质5。

**替代之后变黑**正好抵消删除黑色节点带来的黑高减一。

---

### 二、没有孩子（删除叶子节点）

如果删除的是没有孩子的节点，就要观察被删除节点的颜色分类讨论。

#### 1.删除红色节点

> **直接删除，无需任何调整**

这种情况下删除红色节点不会影响黑高，删除没有任何影响，所以可以直接删除

#### 2.删除黑色节点(引入双黑节点)

如果删除的节点是黑色节点，就把这个节点删除后标记为双黑节点，然后进入处理双黑节点的流程，这也是红黑树删除中最为复杂的流程，分类讨论也集中在此。

---

### 三、处理双黑节点

第一步：检查兄弟节点颜色

#### 1.兄弟节点是黑色

进一步检查兄弟节点的子节点

##### 	(1)兄弟节点至少有一个红色子节点

用下图结构举个例子，只包含父子关系，不包含左右关系。图中的d就是double black节点，`s`是黑色，r是红色。

```C++
        p
       / \
      s   d
     /
    r
```

对于这种情况，需要判定p,s,r三个节点的位置关系，原理见四种旋转类型，对于s有两个红色子节点的情况，优先LL和RR。

判断好形态后，先别着急旋转，先按中序变色：从r开始，到p结束

对于LL和RR来说，是

- `r`变为`s`的颜色
- `s`变为`p`的颜色
- `p`变为黑色。

但对LR和RL来说，是

- `r`变为`p`的颜色
- `p`变为黑色

然后按照四种旋转类型进行关于p的旋转，然后将双黑变为单黑。

##### (2)兄弟节点的子节点都是黑色

将兄弟节点变为红色，然后将双黑上移。

这里的上移指的是**将双黑属性交给当前节点的父节点，然后该节点变为单黑节点**。

- 如果父节点是红色或者根节点：父节点变为单黑，双黑处理完毕
- 如果父节点是黑色：父节点变为双黑，然后处理父节点的双黑

#### 2.兄弟节点是红色

将兄弟节点和父节点的颜色交换，然后对父节点p进行旋转，旋转方向取决于双黑节点和父节点p的关系。如果d是左孩子则左旋，右孩子则右旋。

旋转结束后重新处理双黑节点。
