# 编译与链接的整体流程

一个 C++ 程序从源代码变成可执行文件，通常经历四个阶段：

```text
源文件 .cpp
   │
   ▼
预处理 Preprocessing
   │
   ▼
编译 Compilation
   │
   ▼
汇编 Assembly
   │
   ▼
链接 Linking
   │
   ▼
可执行文件
```

下面逐一说明

---

## 一、预处理

预处理阶段由预处理器完成，主要处理以`#`开头的指令：

- `#include`：把头文件内容插入到当前位置；
- `#define`：宏替换；
- `#ifdef`/`#ifndef`/`#endif`：条件编译；
- 删除注释
- 处理`#pragma`等。

```C++
#include <iostream>
#define MAX 100

int main() {
    std::cout << MAX << std::endl;
}
```

预处理后，`#include <iostream>` 会被替换成 `iostream` 头文件的实际内容，`MAX` 会被替换成 `100`。

---

## 二、编译

编译阶段会把预处理后的代码翻译成汇编代码，这个阶段会进行：

- 词法分析；
- 语法分析；
- 语义分析；
- 类型检查；
- 生成中间代码；
- 优化；
- 生成汇编代码。

注意：**编译阶段只处理单个翻译单元**。
编译器此时不知道其他 `.cpp` 文件中定义了什么函数或变量。
如果当前文件调用了外部函数，编译器只能先记下“这里引用了某个符号”，把解析留给链接阶段。

---

## 三、汇编

汇编阶段把汇编代码翻译成**机器码**，生成**目标文件**，通常是 `.o` 或 `.obj`。

目标文件中包含：

- 机器指令；
- 已定义符号；
- 未定义符号（等待链接时解析）；
- 重定位信息；
- 调试信息等。

例如：

```C++
// a.cpp
int add(int a, int b) {
    return a + b;
}
```

编译汇编后，`add` 是目标文件 `a.o` 中**已定义**的符号。

```C++
// main.cpp
int add(int a, int b);  // 声明

int main() {
    return add(1, 2);
}
```

编译汇编后，`main` 是 `main.o` 中已定义的符号，而 `add` 是**未定义**符号，需要在链接阶段找到它的定义。

## 四、链接

链接阶段把多个目标文件和库组合成一个可执行文件。

链接器主要做两件事：

1. **符号解析**
   找到每个未定义符号对应的定义。
   比如 `main.o` 中的 `add` 未定义，链接器会去 `a.o` 或其他库中找 `add` 的定义。
2. **重定位**
   把各个目标文件中的代码和数据合并，修正地址引用，让程序知道自己被加载到内存后各部分的实际地址。

链接的输入通常是：

- 多个 `.o` / `.obj` 文件；
- 静态库 `.a` / `.lib`；
- 动态库 `.so` / `.dll`。

输出是可执行文件或动态库。

# 头文件的作用与 `#include` 

在 C++ 中，头文件通常用来存放**声明**，而源文件用来存放**定义**。头文件的核心作用是：让多个源文件共享同一份声明，避免重复书写，并保证声明一致。

------

## 一、为什么需要头文件

假设我们有一个函数 `add`，在 `add.cpp` 中定义：

```C++
// add.cpp
int add(int a, int b) {
    return a + b;
}
```

现在 `main.cpp` 想调用它。
编译器在编译 `main.cpp` 时，必须知道 `add` 的名字、参数类型和返回类型，否则无法检查调用是否正确。

所以 `main.cpp` 中需要写：

```C++
int add(int a, int b);  // 声明
```

但如果很多文件都要用 `add`，每个文件都手写一遍声明，很容易写错或不一致。
于是我们把声明放到头文件里：

```C++
// add.h
#ifndef ADD_H
#define ADD_H

int add(int a, int b);

#endif
```

然后每个源文件只需要：

```C++
#include "add.h"
```

这样就共享了同一份声明。

------

## 二、`#include` 的本质

`#include` 是预处理指令。
它的作用非常直接：

> **把指定文件的内容，原封不动地插入到当前文件这一行所在的位置。**

例如：

```C++
// main.cpp
#include "add.h"

int main() {
    return add(1, 2);
}
```

预处理后，`main.cpp` 会变成类似：

```C++
// add.h 的内容被插入到这里
int add(int a, int b);

int main() {
    return add(1, 2);
}
```

所以 `#include` 不是“导入模块”，而是**文本替换**。

------

## 三、`#include <>` 与 `#include ""` 的区别

两种写法：

```C++
#include <iostream>   // 尖括号
#include "add.h"      // 双引号
```

区别在于搜索路径：

- `#include <...>`：优先在**系统头文件目录**中查找，比如标准库目录。
- `#include "..."`：优先在**当前源文件所在目录**查找，找不到再去系统目录。

通常：

- 标准库头文件用 `<>`；
- 自己项目的头文件用 `""`。

但具体搜索顺序由编译器实现决定，不同编译器可能略有差异。

------

## 四、头文件保护

如果同一个头文件被多次包含，可能导致重复定义。
例如：

```C++
// a.h
#include "b.h"

// c.h
#include "b.h"

// main.cpp
#include "a.h"
#include "c.h"
```

预处理后，`b.h` 的内容会被插入两次。
如果 `b.h` 里有函数定义或类定义，就会重复定义，编译报错。

解决办法是**头文件保护**。

### 1. 传统宏保护

```C++
// add.h
#ifndef ADD_H
#define ADD_H

int add(int a, int b);

#endif
```

第一次包含时，`ADD_H` 未定义，内容被插入，并定义 `ADD_H`。
第二次包含时，`ADD_H` 已定义，整个内容被跳过。

### 2. `#pragma once`

```C++
#pragma once

int add(int a, int b);
```

`#pragma once` 是编译器扩展，不是 C++ 标准，但被广泛支持。
它让头文件在同一个翻译单元中只被包含一次，写法更简洁。

------

## 五、头文件的内容

头文件通常放**声明**，而不是定义：

- 函数声明；
- 类定义；
- 模板定义；
- 常量声明；
- 类型别名；
- 宏定义；
- 内联函数定义。

例如：

```C++
// student.h
#pragma once

#include <string>

class Student {
public:
    Student(std::string name, int age);
    void print() const;

private:
    std::string name_;
    int age_;
};
```

对应的源文件：

```C++
// student.cpp
#include "student.h"
#include <iostream>

Student::Student(std::string name, int age)
    : name_(std::move(name)), age_(age) {}

void Student::print() const {
    std::cout << name_ << " " << age_ << std::endl;
}
```

注意：

- 类定义通常放在头文件；
- 成员函数定义通常放在 `.cpp` 中；
- 模板和内联函数通常也放在头文件，因为编译器需要看到定义才能实例化。



# 声明与定义的区别

在 C++ 中，**声明**和**定义**是两个不同但相关的概念。理解它们的区别，是理解编译、链接、头文件和 ODR 的基础。

------

## 一、核心区别

一句话概括：

> **声明**告诉编译器“有这么个名字，它是什么类型”。
> **定义**告诉编译器“这个名字对应的实体具体是什么”，并且通常会分配存储空间或提供函数体。

更具体地说：

- 声明：引入名字，描述类型，不分配存储，不提供实现。
- 定义：提供实体的完整信息，分配存储，或给出函数体。

大多数情况下，**定义同时也是声明**，但声明不一定是定义。

------

## 二、变量的声明与定义

### 1. 声明

```C++
extern int x;   // 声明：x 是一个 int，定义在别处
```

这里没有分配内存，只是告诉编译器 `x` 这个名字存在，类型是 `int`。

### 2. 定义

```C++
int x;          // 定义：分配内存，默认初始化为 0
int y = 10;     // 定义：分配内存，并初始化为 10
```

这两个都会为变量分配存储空间。

### 3. 对比

```C++
extern int a;   // 声明，不分配空间
int b;          // 定义，分配空间
int c = 5;      // 定义，分配空间并初始化
```

注意：

- `extern int a;` 是声明；
- `extern int a = 10;` 是定义，因为给了初始值；
- 同一个变量可以声明多次，但只能定义一次。

------

## 三、函数的声明与定义

### 1. 声明

```C++
int add(int a, int b);   // 函数声明，也叫函数原型
```

它只告诉编译器：

- 函数名是 `add`；
- 参数是两个 `int`；
- 返回类型是 `int`。

没有函数体。

### 2. 定义

```C++
int add(int a, int b) {
    return a + b;
}
```

它提供了函数体，是真正的实现。

### 3. 对比

```C++
int add(int, int);        // 声明，可以多次
int add(int a, int b) {   // 定义，只能一次
    return a + b;
}
```

函数声明通常放在头文件里，函数定义放在 `.cpp` 文件里。

------

## 四、类的声明与定义

### 1. 类声明

```C++
class Student;   // 前向声明
```

这叫前向声明。它告诉编译器：

- 有一个类叫 `Student`；
- 但现在还不知道它有哪些成员。

前向声明常用于指针或引用：

```C++
class Student;

void f(Student* s);   // 可以，因为这里只需要知道 Student 是个类型
```

但不能定义 `Student` 对象，因为编译器不知道它的大小：


```C++
class Student;

Student s;   // 错误：Student 不完整
```

### 2. 类定义

```C++
class Student {
public:
    Student(std::string name, int age);
    void print() const;

private:
    std::string name_;
    int age_;
};
```

类定义给出了完整成员信息，编译器知道它的大小和布局。

### 3. 成员函数的声明与定义

类内：

```C++
class Student {
public:
    void print() const;   // 声明
};
```

类外：

```C++
void Student::print() const {   // 定义
    std::cout << name_ << std::endl;
}
```

如果直接在类内写函数体：

```C++
class Student {
public:
    void print() const {
        std::cout << name_ << std::endl;
    }
};
```

这既是声明也是定义，并且默认是 `inline` 的。

------

## 五、声明可以多次，定义只能一次

这是 C++ 的 **ODR**（One Definition Rule，单一定义规则）的一部分：

- 同一个实体可以声明多次；
- 但在整个程序中只能定义一次。

例如：

```C++
// a.h
extern int x;   // 声明

// a.cpp
int x = 10;     // 定义

// b.cpp
extern int x;   // 再次声明，没问题
```

如果两个 `.cpp` 都写：

```C++
int x = 10;   // 两个定义
```

链接时就会报“重复定义”错误。

------

## 六、常见误区

1. **以为 int x; 只是声明**
   在全局作用域，`int x;` 是定义，会分配存储。
   只有加 `extern` 且不带初始化，才是声明。

2. **以为函数声明可以省略参数名**
   可以省略，但建议保留，便于阅读：



   ```C++
   int add(int, int);        // 合法
   int add(int a, int b);    // 更清晰
   ```

3. **以为类内成员函数定义和普通函数定义一样**
   类内定义的成员函数默认是 `inline`，可以放在头文件中，不会违反 ODR。

4. **忘记前向声明不能用于定义对象**
   前向声明只适合指针、引用和函数参数，不能用于需要完整类型的场景。


# 链接过程——符号解析与重定位

编译阶段只处理单个源文件，每个 `.cpp` 被编译成一个目标文件 `.o`（或 `.obj`）。目标文件里已经包含了机器指令，但很多外部引用还没有确定地址，比如：

```C++
// main.cpp
int add(int, int);   // 声明

int main() {
    return add(1, 2);
}
```

编译 `main.cpp` 时，编译器知道 `add` 的签名，但不知道 `add` 的代码在哪里。
于是它在目标文件里留下一个**未定义符号** `add`，等待链接器处理。

链接器的核心任务就是两件事：

1. **符号解析**：找到每个未定义符号对应的定义。
2. **重定位**：把各个目标文件的代码和数据合并，并修正地址引用。

------

## 一、目标文件中的符号

目标文件里有一张**符号表**，记录了该文件定义和引用的符号。

符号大致分为几类：

- **已定义符号**：当前目标文件提供了定义的函数或全局变量。
- **未定义符号**：当前目标文件引用了，但定义在别处。
- **局部符号**：只在文件内部可见，比如 `static` 函数或 `static` 全局变量。

例如：

```C++
// add.cpp
int add(int a, int b) {
    return a + b;
}
```

编译后，`add.o` 的符号表中，`add` 是**已定义符号**。

```C++
// main.cpp
int add(int a, int b);  // 声明

int main() {
    return add(1, 2);
}
```

编译后，`main.o` 的符号表中，`main` 是已定义符号，`add` 是**未定义符号**。

------

## 二、符号解析

链接器扫描所有目标文件和库，建立一张全局符号表。

对于每个未定义符号，链接器去其他目标文件或库中查找同名的已定义符号。

如果找到，就把引用和定义关联起来。
如果找不到，就报错：

```
undefined reference to `add(int, int)'
```

这就是常见的“未定义引用”错误。

如果找到多个定义，也可能报错：

```
multiple definition of `add(int, int)'
```

这就是“重复定义”错误。

符号解析的关键规则：

- 每个未定义符号必须恰好找到一个定义；
- 每个已定义符号只能定义一次（ODR）；
- 强符号不能重复，弱符号可以。

------

## 三、重定位

符号解析完成后，链接器知道每个符号最终属于哪个目标文件。
但此时还没有确定这些代码和数据在最终可执行文件中的**运行时地址**。

重定位就是：

1. **合并节**：把所有目标文件的 `.text`、`.data`、`.bss` 等节合并到一起。
2. **分配地址**：为合并后的每个节分配虚拟地址。
3. **修正引用**：修改指令中涉及外部符号或地址的地方，填入正确的地址。

举个例子：

```C++
// main.cpp
extern int x;
int main() {
    return x;
}
```

```C++
// data.cpp
int x = 42;
```

编译后：

- `main.o` 中有一条指令要读取 `x`，但它不知道 `x` 的地址；
- `data.o` 中定义了 `x`，它知道 `x` 在自己的 `.data` 节中。

链接时：

1. 合并 `.text`、`.data` 等节；
2. 给 `x` 分配最终地址，比如 `0x404000`；
3. 修改 `main.o` 中读取 `x` 的指令，把地址填成 `0x404000`。

这个过程就是重定位。

------

## 四、一个完整流程示例

假设有两个文件：

```C++
// add.cpp
int add(int a, int b) {
    return a + b;
}
```

```C++
// main.cpp
#include <iostream>

int add(int a, int b);

int main() {
    std::cout << add(3, 4) << std::endl;
    return 0;
}
```

编译：

```bash
g++ -c add.cpp -o add.o
g++ -c main.cpp -o main.o
```

此时：

- `add.o`：定义 `add`，未定义 `std::cout` 相关符号；
- `main.o`：定义 `main`，未定义 `add` 和 `std::cout` 相关符号。

链接：


```bash
g++ add.o main.o -o app
```

链接器：

1. 从 `add.o` 找到 `add` 的定义，解析 `main.o` 中对 `add` 的未定义引用；
2. 从标准库找到 `std::cout` 等符号的定义；
3. 合并所有节，分配地址；
4. 重定位所有引用，生成可执行文件 `app`。

------

## 五、静态库与动态库的链接差异

- **静态库**（`.a` / `.lib`）：
  链接时，链接器把用到的目标代码**复制**到可执行文件中。
  程序运行时不再需要静态库。
- **动态库**（`.so` / `.dll`）：
  链接时只记录依赖关系，不复制代码。
  程序运行时由动态加载器加载动态库，并解析符号。

动态库的符号解析可能延迟到运行时，所以错误可能出现在程序启动或运行中，而不是链接时。

# 常见问题——重复定义、未定义引用与 ODR

在编译链接过程中，最常见的两类错误是：

- **未定义引用**：链接器找不到某个符号的定义。
- **重复定义**：同一个符号被定义了多次。

这两类错误都和 C++ 的 **ODR**（One Definition Rule，单一定义规则）密切相关。

------

## 一、未定义引用

未定义引用通常发生在链接阶段，错误信息类似：

```
undefined reference to `add(int, int)'
```

含义是：某个目标文件引用了 `add`，但链接器在所有目标文件和库中都找不到它的定义。

常见原因：

1. **只写了声明，没有写定义**

   ```C++
   // main.cpp
   int add(int, int);   // 声明

   int main() {
       return add(1, 2);
   }
   ```

   如果没有任何文件定义 `add`，链接时就报未定义引用。

2. **定义在另一个 .cpp 中，但链接时没有把它加进来**

   ```bash
   g++ main.cpp -o app          # 忘了 add.cpp
   ```

   应该：

   ```bash
   g++ main.cpp add.cpp -o app
   ```

3. **函数签名不一致**

   ```C++
   // 声明
   int add(int, int);

   // 定义
   double add(double, double) { ... }
   ```

   这其实是两个不同的函数，声明和定义不匹配，链接器找不到 `int add(int, int)`。

4. **忘记链接某个库**

   例如使用了 `pthread`，但链接时没加 `-lpthread`。

5. **C 和 C++ 混合编译时没有 extern "C"**

   C++ 会对函数名进行名字修饰，C 不会。
   如果 C 文件定义了函数，C++ 文件直接声明，链接时会找不到符号。
   需要用：

   ```C++
   extern "C" {
       int c_function(int);
   }
   ```

------

## 二、重复定义

重复定义错误通常也发生在链接阶段：

```
multiple definition of `x'
```

含义是：同一个符号在多个目标文件中都有定义。

常见原因：

1. **全局变量定义在头文件中**

   ```C++
   // a.h
   int x = 10;   // 这是定义
   ```

   如果 `a.h` 被多个 `.cpp` 包含，每个 `.cpp` 都会生成一个 `x` 的定义，链接时冲突。

   正确做法：

   ```c++
   // a.h
   extern int x;   // 声明

   // a.cpp
   int x = 10;     // 定义
   ```

2. **函数定义在头文件中，但没有 inline**

   ```C++
   // a.h
   int add(int a, int b) {
       return a + b;
   }
   ```

   如果被多个 `.cpp` 包含，每个翻译单元都会生成一个 `add` 的定义，链接冲突。

   正确做法：

   - 加 `inline`：

     ```C++
     inline int add(int a, int b) {
         return a + b;
     }
     ```

   - 或者把定义放到 `.cpp`，头文件只留声明。

3. **类内定义的成员函数默认是 inline**

   ```C++
   class A {
   public:
       void f() { }   // 默认 inline，可以放在头文件
   };
   ```

   所以类内直接写函数体通常不会导致重复定义。

4. **模板和内联函数可以放在头文件**

   因为它们允许在多个翻译单元中出现相同定义，只要完全一致。

------

## 三、ODR：单一定义规则

ODR 是 C++ 的核心规则之一，主要内容是：

> **在同一个程序中，每个非内联函数、非内联变量、类类型、模板等，只能有一个定义。**

更具体地说：

- 对于**非内联函数和全局变量**：整个程序中只能定义一次。
- 对于**类、模板、内联函数**：可以在多个翻译单元中定义，但每个定义必须完全相同，且每个翻译单元最多一个。
- 对于**局部变量和静态局部变量**：作用域和生命周期受限于所在作用域。

违反 ODR 通常不会在编译单个文件时报错，而是在链接时或运行时表现为：

- 重复定义错误；
- 未定义引用；
- 未定义行为。

------

## 四、头文件保护不能解决重复定义

注意：

```C++
#ifndef A_H
#define A_H
...
#endif
```

或

```C++
#pragma once
```

只能防止**同一个翻译单元内重复包含**同一个头文件。
它不能防止**多个 .cpp 文件各自包含该头文件后，各自生成一份定义**。

例如：

```C++
// a.h
#pragma once
int x = 10;   // 定义
```

```c++
// main.cpp
#include "a.h"

// other.cpp
#include "a.h"
```

两个 `.cpp` 各自包含一次 `a.h`，各自都有一个 `int x = 10;` 的定义，链接时仍然重复定义。
所以头文件保护解决的是“重复包含”，不是“重复定义”。

------

## 五、如何避免这些错误

1. **头文件只放声明，定义放 .cpp**

   ```C++
   // student.h
   extern int student_count;

   void print();

   // student.cpp
   int student_count = 0;

   void print() { ... }
   ```

2. **需要放头文件的函数用 inline**

   ```C++
   inline int add(int a, int b) {
       return a + b;
   }
   ```

3. **模板、类定义、类内成员函数可以放头文件**

4. **全局变量用 extern 声明，在某个 .cpp 中定义一次**

5. **内部链接符号用 static 或匿名命名空间**

   ```C++
   static int helper() { ... }
   ```

   或

   ```C++
   namespace {
       int helper() { ... }
   }
   ```

   这样每个翻译单元有自己独立的一份，不会与其他文件冲突。

6. **编译链接时确保所有需要的目标文件和库都参与链接**
