# 池化(Pooling)

## 一、池化的动机

为什么池化能优化GC？池化优化了什么？
要解答以上两个问题，要先搞清楚一次普通的分配，到底“贵”在哪里

在.NET中，在托管堆上分配一个小对象，本质上只是移动一个指针。由于Gen0是一片连续内存，分配就是“指针往前挪一格”，所以分配动作几乎就是零成本。真正的成本并不是分配本身，而是分配引发的后续。

### 代价一：分配速率越高，GC越频繁

GC的触发条件之一是"Gen0预算被填满"。分配的越快，GC就被触发得越频繁——GC的代价可不低。

### 代价二：存活对象带来的晋升开销 

在每轮GC结束后，Gen0、Gen1中存活的对象都会往上晋升一级，晋升的过程包括：

- 将对象复制到更老的一代
- 更新引用、修正指针

如果一个对象被反复创建又短暂存活，它可能被复制多次，纯属浪费。

### 代价三：大对象堆的额外压力

LOH只在Gen2回收时处理，回收后默认不压缩，更容易触发碎片化问题

举一个直观的例子：

```C#
// 每个请求都 new 一个 100KB 的 byte[]
void HandleRequest()
{
    byte[] buffer = new byte[100_000];  // 落到 LOH
    // ... 用完就丢
}
```

在计算机高速运行下，每秒都会产生上千个LOH对象，快速堆高Gen2的回收频率。问题在于：这些对象用一次就扔，但我们却承担了分配、回收、晋升、碎片化的全套代价

池化要解决的就是这个问题：既然对象的内容可以重用，那对象本身也应该可以重用。
